- `chat_messages`: id, sender_id, receiver_id, message, project_id, is_read, created_at

### Technical Implementation Guidelines

#### Query Patterns to Use
- **SELECT**: Always specify columns instead of `*` when possible
- **FILTERS**: Use `.eq()`, `.neq()`, `.gt()`, `.lt()`, `.like()`, `.textSearch()`
- **SORTING**: `.order(column, { ascending: false })`
- **LIMITING**: `.range(start, end)` or `.limit(count)`
- **JOINS**: Use Supabase relation syntax: `table!inner(column)` or `table!left(column)`
- **REAL-TIME**: Use `supabase.channel().on('postgres_changes', ...)` for live updates

#### Error Handling Pattern
```javascript
const { data, error } = await supabase
  .from('table')
  .select('*')
  .eq('id', someId);

if (error) {
  setError(error.message);
  return;
}
// Process data
```

#### Loading States
- Show skeleton loaders while data fetches
- Handle empty states gracefully
- Provide retry mechanism for failed requests

#### Authentication Requirements
- Screens needing user context: Get user from `supabase.auth.getUser()`

- Role-based access: Check `user.role` for faculty/student specific features
